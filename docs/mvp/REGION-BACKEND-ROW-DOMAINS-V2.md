# Closed row domain retirement: disposal-argument variant

This private variant passes the closing forwarding owner to the child disposer instead of storing owner and native-marker fields on every live native frame. All guards and individual cleanup fallbacks remain. It passes 474 backend tests plus an additional mechanism probe (475 unique), 71 compatibility tests, 112 browser cycles and fake/real DOM collection controls.

A direct ten-Job cohort covers all seven list operations at 100 and 1,000 rows using verified candidate and accepted bundles, AA controls and AB/BA. Clear1000 is 1.002 times the accepted CPU (orders0.971/1.035); create1000 is1.093 (orders1.109/1.077); select1000 is1.103 (orders1.030/1.167). The earlier clear improvement does not reproduce with this implementation. It is rejected before further full-matrix spending, and every active backend source is restored byte-for-byte to the accepted unified-native-ticket review. The full matrix would still have been required before adoption.

The diagnostic history retains 30 successful serial bounded Jobs (18 semantic, one keyed build, ten direct comparison, one post-restore focused suite) and one failed staging Job caused by a missing dependency-lock.json copy. That harness omission was fixed in a new output directory; the failed run is not reported as a framework or resource failure. All original limits remain.

The implementation-specific mechanism test is retained in the evaluation capsule and removed from the restored active tests. Four additional semantic tests remain and pass on the restored backend. Neither row-domain variant is adopted. Public compiler/runtime and Surface remain unchanged. Practical Svelte parity is not achieved; further work targets unified task records in generic views.
