## Outcome

A developer can create, edit, check, build and preview a small local component
application using a documented Surface subset, with predictable original-source
feedback and explicit unsupported behavior. This is a usable early product,
not complete Surface v0.3 or production framework certification.

The [technical verification gate](../docs/mvp/VERIFICATION.md) now runs check,

The [headless Linux gate](../docs/mvp/HEADLESS-VERIFICATION.md) initially passed the

`verify:mvp` now defaults to that headless launcher, with no desktop fallback.
The Windows GUI route is an explicit `verify:windows` command and is not run
as an unsolicited follow-up.

For each increment, preserve the regression baseline and repeat the relevant
native/browser workflow when behavior changes. Define latency targets using a
representative project before making performance-driven implementation choices.

## Deferred scope

The owner-requested [capability backlog](../docs/mvp/ECOSYSTEM-ROADMAP.md#owner-requested-capability-backlog-dx-throughout)
maps reactive composition/effects, shared state, remote data, persistence,
SSR/hydration, refresh/HMR, Server Components, Server Actions, schemas and bundler
adapters. Every capability carries DX acceptance and dependency questions. It is
future work to prioritize when appropriate, not an expansion of this MVP gate or
a claim that those capabilities are implemented.

Rust ports, full v0.3 grammar, generalized packaging, all recovery cases,
cross-language rename, multiple/remote workspaces, SSR, authorization systems,
nonces and sealed transport need their own prioritization. None is automatically
part of this MVP or a reason to reopen every completed spike.
